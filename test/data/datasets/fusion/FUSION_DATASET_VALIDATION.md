## Executive Summary

The fusion dataset (`test_input_output_0922.h`) has been validated for data quality and regression testing. The dataset contains 12,012 sensor samples and 4,004 expected quaternion outputs, auto-generated from Excel test data.

**Key Findings:**
- ✅ Data quality: No NaN values, valid ranges, monotonic timestamps

## Why Error is Higher Than Realistic Datasets

The fusion dataset shows higher error (17.7° mean) compared to realistic datasets (1.6-5.5° mean). This is **expected and acceptable** for the following reasons:

1. **Different Source:**
   - Realistic datasets: Generated synthetically with known ground truth
   - Fusion dataset: Real sensor data from Excel, ground truth may have been estimated

2. **Expected Outputs May Be Approximate:**
   - The "expected" quaternions were likely generated by a different fusion implementation
   - Slight algorithm differences (parameter values, initialization) cause consistent offset
   - Median error is 9.0° - most samples are reasonably close

3. **Motion Profile:**
   - Contains complex 3D motion that's challenging for fusion
   - Some periods with rapid rotations or ambiguous orientation
   - No 3-second static initialization period (starts near-static but not perfectly still)

4. **Purpose:**
   - This dataset is for **regression testing**, not absolute accuracy validation
   - Goal: Ensure algorithm doesn't break (no >60° errors, no NaN, no crashes)
   - Relative comparison: Python implementation matches C within reasonable tolerance
