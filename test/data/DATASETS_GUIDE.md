# Test Data Organization Guide

## Overview

The test data is organized into two main categories:

1. **datasets/** - Raw data files (CSV, Excel) for end-to-end testing
2. **testdata/** - Preprocessed C header files for unit/integration testing

## Directory Structure

```
test/data/
├── datasets/
│   ├── synthetic/          # Generated synthetic IMU data with ground truth
│   ├── repoimu/           # Real IMU data from RepoIMU dataset (Vicon reference)
│   ├── fiumargdb/         # Real IMU data from FIUMARG-DB dataset
│   └── localFSdataset/    # Original Excel testdata files (legacy)
│
└── testdata/
    ├── quaternion/        # Unit test vectors for quaternion math
    ├── matrix/            # Unit test vectors for matrix operations
    ├── fusion/            # Integration test data (sensor inputs + expected outputs)
    └── trigmath/          # Unit test vectors for trigonometry functions
```

## 1. datasets/ - Runtime Test Data

### Purpose
Runtime data files used by E2E (end-to-end) tests. These contain real or synthetic IMU sensor measurements along with ground truth orientation.

### Format
- **File types**: CSV, Excel (.xlsx)
- **Data**: Time-series sensor readings with timestamps
- **Ground truth**: Quaternions and/or Euler angles
- **Usage**: Loaded at test runtime using file I/O

### Datasets

#### synthetic/
- **Generated by**: `scripts/generate_synthetic_datasets.py`
- **Sensors**: MPU9250 (accel/gyro) + AK8963 (magnetometer)
- **CSV format**:
  ```
  timestamp_ns,accel_x,accel_y,accel_z,gyro_x,gyro_y,gyro_z,mag_x,mag_y,mag_z,gt_roll,gt_pitch,gt_yaw,gt_qw,gt_qx,gt_qy,gt_qz
  ```
- **Scenarios**:
  - Static (no movement)
  - Rotation sequences (X, Y, Z axes)
  - Vibration (simulated walking/running)
  - High noise/bias conditions
  - Complex 3D motion
- **Tests using this**:
  - `test_6axis_synthetic.c`
  - `test_9axis_synthetic.c`

#### repoimu/
- **Source**: RepoIMU public dataset (ETH Zurich)
- **Reference**: Vicon optical motion capture system (sub-mm accuracy)
- **CSV format**: Semicolon-delimited
  ```
  timestamp;quat_w;quat_x;quat_y;quat_z;acc_x;acc_y;acc_z;gyro_x;gyro_y;gyro_z;mag_x;mag_y;mag_z
  ```
- **Files**:
  - `TStick_Test01_Static.csv` - Static upright position
  - `TStick_Test02_Trial1.csv` - Dynamic movement
- **Tests using this**:
  - `test_6axis_e2e.c`
  - `test_9axis_e2e.c`

#### fiumargdb/
- **Source**: FIUMARG-DB magnetometer dataset
- **Purpose**: Test magnetometer calibration and 9-axis fusion
- **Format**: CSV with magnetic field data
- **Tests using this**:
  - `test_6axis_fiumargdb.c`
  - `test_9axis_fiumargdb.c`

#### localFSdataset/
- **Source**: Original Excel files from algorithm development
- **Format**: Microsoft Excel 2007+ (.xlsx)
- **Contents**:
  - Sensor input data (raw counts)
  - Expected algorithm outputs (quaternions)
  - Various motion scenarios
- **Status**: Legacy data - converted to C headers in `testdata/fusion/`
- **Files**:
  - `TestData_Quatmath.xlsx` - Quaternion math validation
  - `True90test*.xlsx` - 90-degree rotation tests
  - `test_input_output_*.xlsx` - Algorithm validation datasets

## 2. testdata/ - Compiled Test Vectors

### Purpose
Preprocessed test vectors compiled directly into test executables as C header files. Used for fast unit and integration testing without file I/O.

### Format
- **File type**: C header files (.h)
- **Data**: Static const arrays
- **Usage**: #include in test source files

### Test Vectors

#### quaternion/
- **Unit tests for**: `algo_sf_quatmath.c`
- **Test vectors**:
  - `TestData_NormQ.h` - Quaternion normalization
  - `TestData_ProdPQ.h` - Quaternion multiplication
  - `TestData_QIntegrate.h` - Quaternion integration
  - `TestData_QIntegrate1.h` - Extended integration tests
  - `TestData_Quat2RotMtx.h` - Quaternion to rotation matrix
  - `TestData_RotMtx2Quat.h` - Rotation matrix to quaternion
  - `TestData_RotMtx2Angles.h` - Rotation matrix to Euler angles
- **Source**: Converted from `datasets/localFSdataset/TestData_Quatmath.xlsx`
- **Tests using this**: `test_quatmath.c`

#### matrix/
- **Unit tests for**: `algo_sf_matrixmath.c`
- **Test vectors**: Matrix operations (empty - to be added)
- **Tests using this**: `test_matrixmath.c`

#### fusion/
- **Integration tests for**: `algo_sf_6x_sensor_fusion.c`, `algo_sf_9x_sensor_fusion.c`
- **Test vectors**:
  - `test_input_output_0922.h` - 12,012 input samples, 4,004 output samples
  - `test_input_output_0923_standstill.h` - Standstill scenario
  - `test_input_output_0923_moving.h` - Moving scenario
  - `test_input_output_0930.h` - Additional validation
  - `test_input_output_1012.h` - Additional validation
- **Source**: Converted from `datasets/localFSdataset/test_input_output_*.xlsx`
- **Format**:
  ```c
  typedef struct {
      uint32_t id;      // Sensor ID: 0=accel, 1=gyro, 2=mag
      int16_t x, y, z;  // Sensor readings (raw counts)
      uint64_t ts;      // Timestamp (nanoseconds)
  } test_sensor_sample_t;

  typedef struct {
      float q0, q1, q2, q3;     // Expected quaternion output (q0=w, q1=x, q2=y, q3=z)
      float roll, pitch, yaw;   // Expected Euler angles (degrees) - MAY BE ZERO
      uint64_t ts;              // Timestamp
  } test_expected_output_t;
  ```
- **Important**: Euler angles (roll, pitch, yaw) are often 0.000f because the original Excel data only contained quaternion ground truth
- **Tests using this**: `test_fusion_testdata.c` (currently under development/debug)

#### trigmath/
- **Unit tests for**: Trigonometry and approximation functions
- **Test vectors**: To be added

## Dataset Selection Guidelines

### Use datasets/ when:
- Testing end-to-end system performance
- Need realistic sensor noise and dynamics
- Want to test with publicly validated datasets (RepoIMU, FIUMARG)
- Testing long-duration scenarios
- Need flexibility to add/modify test cases

### Use testdata/ when:
- Testing specific algorithm components (quaternion math, matrix ops)
- Need fast execution (no file I/O)
- Regression testing against known outputs
- Unit testing individual functions
- Want deterministic, repeatable results

## Data Conversion

### Excel → testdata/ headers
Original Excel files in `datasets/localFSdataset/` have been converted to C headers in `testdata/`.

**Conversion process** (for reference):
1. Excel file contains sensor inputs and expected outputs
2. Python/MATLAB script extracts data
3. Generates C header with static const arrays
4. Header included directly in test source

**Files converted**:
- `TestData_Quatmath.xlsx` → `testdata/quaternion/TestData_*.h`
- `test_input_output_*.xlsx` → `testdata/fusion/test_input_output_*.h`

## Known Issues

### test_fusion_testdata.c failures
**Symptom**: Large quaternion errors (83° mean error)

**Possible causes**:
1. **Ground truth quaternion convention mismatch**
   - Test expects (w, x, y, z) order
   - Excel data may have (x, y, z, w) order
   - Need to verify quaternion component ordering

2. **Sensor scaling mismatch**
   - Test uses MPU9250 scales:
     - Accel: 16384 counts/g
     - Gyro: 131 counts/dps
   - Excel data may use different sensor specs

3. **Coordinate frame mismatch**
   - Algorithm uses custom Euler convention
   - Excel ground truth may use different convention

4. **Timestamp/sample alignment issues**
   - Input samples are interleaved (accel, gyro, mag)
   - Output samples generated only after certain inputs
   - Timestamp matching logic may be incorrect

**Next steps**:
1. Verify quaternion ordering in Excel source files
2. Check sensor scaling factors in Excel metadata
3. Add detailed logging to compare first few samples
4. Consider if Excel data is from different algorithm version

## Maintenance

### Adding new datasets/
1. Place CSV/Excel file in appropriate subdirectory
2. Create or update corresponding E2E test
3. Update CMakeLists.txt with new test target
4. Document format in this file

### Adding new testdata/
1. Create C header with static const arrays
2. Follow existing struct conventions
3. Update corresponding unit test
4. Update CMakeLists.txt if needed
5. Document in this file

## Summary

| Category | Purpose | Format | I/O | Speed | Best For |
|----------|---------|--------|-----|-------|----------|
| **datasets/** | Runtime E2E testing | CSV/Excel | File | Slower | System validation, realistic scenarios |
| **testdata/** | Compile-time unit testing | C headers | Memory | Faster | Component testing, regression |

Both are essential:
- **datasets/** validates the complete system works correctly
- **testdata/** ensures individual components remain correct
